# R5a — Air Drums onset and owned MIDI pulse

A phone/tablet route with the new airStrike signal and Note destination explicitly opts in to gravity-free acceleration onset detection. Existing acceleration CC mappings remain continuous. No additional wire kinds: use the authenticated acceleration stream and existing Enable acceleration button. A strike requires quiet observations below 0.20 for at least 80 ms, then a sample at or above 0.45; a 120 ms refractory interval suppresses rebounds. Defaults refer to the normalized 20 m/s² full scale. Velocity is 25–100% of the route's configured velocity ceiling, then route calibration applies; default note gate threshold/hysteresis are not used for this signal. Settings are validated in the standalone detector, but host currently uses defaults; configurable per-route strike settings and clear UI are future work. A magnitude-only detector cannot reliably infer intentional strikes versus every daily movement.

Pulse owns only its existing acceleration router session and airStrike signal. Host emits Note Off via releaseSignal after 60 ms on the next watchdog/sample service; no hard real-time guarantee. Explicit release, fault, revoke, Stop/Panic remove ownership immediately. Shared held notes follow existing router ownership rules, not forced retriggers. No synthetic note-offs that silence other owners. No new network permissions. The browser may coalesce short peaks, and one ACK lane limits timing; actual drum latency, velocity feel and false positives remain physical HOLD. Do not use vigorous movements or hit a surface with the device.

Four deterministic tests cover onset, quiet/refractory, invalid and stale samples, runtime pulse, independent release and revoke. Stable unchanged; no audio drum kit or preset UI yet.
