# Group gamepad adapter - experimental native host API

Base: #165 exact head 09b93d9f9b5692c1a703bc4c4bdcd235f96f4106, full CI 45594990981 success. This slice is separate from SDK #166 and does not rename or change app identity.

A gamepad-only profile uses the existing PerformanceGroupDelivery and full GamepadFrame normalization. Mixed source profiles fail rather than silently drop mappings. Each explicitly bound slot receives a new token. An old token cannot operate a replacement device. Initial arm, timeout and loss require a neutral full snapshot before playback; ordinary lifts retain the existing toggle semantics, while loss retires all owners of that lease. Duplicate unsmoothed snapshots skip routing but refresh adapter liveness. Smoothed mappings receive repeated samples. The existing 350 ms physical deadline is unchanged. Expiration removes all overdue owners in a batch so an also-expired lower-priority control cannot briefly reappear. A backward or invalid trusted clock fails closed and requires neutral rearm.

The existing process-wide PerformanceGroupMIDIHost exposes startGamepads, bindGamepad, receiveGamepad, expireGamepads and unbindGamepad. It uses the same transactional port registry and MIDI encoder, with mutually exclusive generic/gamepad delivery states. Scoped stop, panic, retry and close preserve delivery debt. The caller must own frozen physical bindings, serialize callbacks, invoke watchdog expiry at the existing cadence, and call unbind on actual disconnect. These APIs do not install GameController handlers, enumerate devices, open ports automatically, or start from the UI. Native adapter exclusivity with the existing BuilderGamepadSource and Studio lifecycle must be proven before wiring the UI. A nil frame is loss, not proof of physical replacement; binding tokens are not hardware IDs.

Seven core tests authored: neutral and stale token, four slots and scoped timeout, batch CC expiry, fault isolation/debt, mixed profile and invalid clock, toggle cleanup, 4000 note edges with duplicate snapshots. Synthetic event counts are correctness evidence, not measured hardware latency or sustainable throughput. Native compile and physical acceptance are separate. Do not merge, install, release or activate live hardware without acceptance.

Next: integrate the existing BuilderGamepadSource with a single exclusive Studio owner and existing polling/event cadence; add start/stop/panic lifecycle, explicit adapter readiness, registered-port projection and DAW confirmation. Trackpad, mouse, Touch Bar, camera and remote adapters still need their own source-specific semantics before mixed profiles are supported. Independent group MPE remains open.

The Studio explicitly opts into the expanded local profile: Xbox slots plus Trackpad and Magic Mouse primary-contact signals x, y, contact and contactSize. All sources share one group delivery ownership graph and the existing port registry. Group routing now orders note-off, control changes (including sustain and bend), then note-on for a single frame; legacy SensorRouter behavior outside groups is unchanged.

Surface startup requires an observed lift before contact can sound. All-nil samples mean observed lift; invalid partial coordinates do not arm a surface. Local receipt timestamps fence stale/out-of-order data, and expiry uses sample receipt time rather than delayed processing time. Surface and controller timeouts remain 350 ms; the existing 20 ms watchdog drains the existing bounded ordered surface mailbox. An overflow, stale batch or invalid native coordinate stops the experimental group performance rather than replaying stale edges. Mouse orientation is frozen for the session. Stop invalidates callbacks and releases MIDI before native monitor teardown. No new native input driver, permission shortcut, haptic output, background activity, or automatic start.

The editor currently freezes configuration while registered ports remain or cleanup is pending. Close retained ports to edit, then Start again; persistent group IDs and planned port names are unchanged by rename or reorder. GarageBand multi-track and MPE are not asserted. Mixed-source native acceptance is not covered by the earlier gamepad-only 491-test result. Four additional regression tests cover mixed sustain ownership, source timing/neutral rearm, effect-before-note ordering, and rejection of unsupported routes. Native/physical acceptance pending.
