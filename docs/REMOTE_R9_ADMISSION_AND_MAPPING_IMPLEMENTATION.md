## 2. Authoritative admission: two independent budgets

### 2.1 Host resource policy as implemented in #87

16 router sessions = five protected local slots (trackpad, Magic Mouse, lid, Touch Bar, camera) + at most eleven remote reserved slots. At most four admitted peers. Host serial authority computes each source's full mapped stream cost from configured routes, not client requests:
- touch (any x/y/contact), tilt (any yaw/pitch/roll), acceleration (including airStrike), rotation, drums (any pad), piano (any key OR sustain), pedals (any pedal): each 0 or 1.
- Cost 1..7 for eligible admitted source. Multiple routes, targets, pointers, notes, pedals or widgets within a stream do not increase its session cost. Air Drums and acceleration count once.
- Admit only if peer count <4 and sum of existing full costs + new cost <=11; no preemption, partial admission, borrowing local slots or client capacity negotiation. In #87 peer-count check occurs before invitation consumption, cost check after; failed attempts may or may not consume invitation depending on stage. UI always clears secret and asks for fresh invitation; never probes/retries it.
- 7+4 fits; 7+7 fails; 3+3+3+2 fits; fifth peer fails even if only five total sessions. Actual allocated sessions may be fewer than reserved. These are resource-only examples, not workload promises.
- Reservation persists through enable/disable, idle, stream release, metadata query and layout change. Only serialized peer removal (disconnect/revoke/expiry/stop) reclaims it. Browser closing socket is not proof that host already removed peer. Existing peers/local owners unchanged on new refusal. No UI offer "release a pedal to let another device pair"; disconnect a whole device at the Mac if capacity must be freed, or reconfigure a smaller patch while all required sessions/peers stopped and re-invite.

No new reservation or refusal response in v8. Existing admission ACK remains exactly admitted or generic failure/close. Host does not disclose remaining slots, peer count, identities, reservation list or reason to unauthenticated or admitted browser. Successful admission on a known #87-derived build means full mapped cost reserved under that policy, not currently active sessions or latency guarantee. v7 masks allow local computation of own mapped cost only; no need to show numeric capacity on Play. If optional idle Setup detail is useful, "Mapped streams: N; reserved for this connection until Mac removes it" only on a verified reservation-aware host; otherwise omit reserved wording. No claim to know actual global utilization.

### 2.2 Independent browser workload eligibility

Resource reservation does not authorize every simultaneous performance combination. #86's paced prototype tested downward-closed families:
| Family (virtual profiles) | Passing combinations /127 | Structure |
|---|---:|---|
| low (5,20,20 +/-10ms) | 126 | all proper nonempty subsets, not all seven |
| moderate (+40,40 +/-15ms) | 60 | singles, all pairs, 31 triples, one four-stream touch+three sensors |
| broad (+60ms) | 35 | seven singles, 15 pairs, 13 triples |
Broad family = at most one discrete stream (touch/drums/piano/pedals) plus at most two of tilt/acceleration/rotation, OR all three sensors; no two discrete streams, no four-stream combination. This family is a conservative *candidate* policy only. It treats touch as discrete even if mapping is continuous; avoids unsafe assumption about hidden target semantics. Do not infer a low/moderate profile from one RTT or local Wi-Fi label. No automatic profile promotion; no additional probes during performance.

Concrete implementation rule: maintain a build-time allowlist of exact tested stream masks (not scalar max-count), initially only independently verified single streams; if no approved single-stream result, preview locked. Broad-family predicate after coordinator approval of exact integrated candidate evidence: d=popcount(mask & discreteMask), s=popcount(mask & sensorMask); allow empty or (d==0 && s<=3) or (d==1 && s<=2), intersect mapped and individually verified streams. For lower-latency expansion use the exact downward-closed approved masks from test data, never a guessed max. Use the prototype family only as a test target until PERF3 validates actual integration. Local browser restriction is a usability guard, not native rate or security authority; old clients still subject to host budget, authorization and watchdog. If a verified policy needs host-enforced active masks in future, that is separate scope.

For activation conservatively count user-enabled streams capable of emitting input (even enabled idle), pending arm/permission, desired/sent/ACKed nonzero states and release-pending until explicitly disabled and released or socket retired. XY has an implicit enabled surface; selecting it is view-only until Enable or an eligible explicit pointer gesture. Do not allow an inactive hidden surface to consume input. Compute prospective union before enabling/requesting permission; if not allowed, leave all existing streams and owners unchanged. Local release frees *browser workload eligibility* only after matching release ACK (or no frame ever sent); it never frees host peer reservation. If no safe refusal for a host-side race, close rather than invent a new ACK.

## 3. v8 mapping protocol: final wire contract

### 3.1 Negotiation and privacy

No change to v1–7 message kinds, v7 exact manifest schema, invitation, TLS, Origin, WebSocket subprotocol, one-pending lane or generic admission failure. Same-origin host page advertises static build support flags mappingV8 and mappingLabelsV8, not URL params or extra v7 fields. Flags are true only for a fully implemented compatible host/page; labels requires mapping flag. Old host/page and old client keep existing v7 or v1–6 behavior (subject to new host reservation policy and security fixes). New page with no v8 support proceeds with logical labels, never probes an old host or downgrades malformed advertised v8.

Mac per-invitation choices: destination details default off; custom labels default off and disabled unless details allowed. Explain paired device can read disclosed MIDI destinations and selected user text. Store consent with pending invitation on host, atomically bind consumed invitation to admitted peer, never trust browser source/consent. Clear on invitation expiration/reissue/cancel, failed admission as appropriate to actual consumption, peer removal and stop; a new invitation always starts defaults off. Revoking consent requires revoke peer and clear state, not hot mutation. Legacy admission unchanged on wire. Browser memory only; no persistent cache, storage, logs, URL, analytics or telemetry for mapping/labels/secrets; same-origin page no-store. Snapshot immutable per connection, based on validated configured patch, admitted phone/tablet source and consent. Existing configure guard prevents peer-active patch edits; no live refresh, revision field or cross-peer cache. Host keeps only bounded eligible projection, not client-accessible raw patch.

Order: TLS/Origin and invitation -> admitted -> v7 valid manifest -> optional v8 mapping pages -> optional label pages if details permitted -> atomically publish capability+metadata -> Ready (all controls Off). If support advertised, metadata phase is mandatory to complete or close; no fallback after malformed response/timeout. No permission prompt or performance input before Ready. During active performance, allow only eligible explicit performance input/arm and release; no idle heartbeat, metadata request or layout/alias editing. Legacy clients may continue established v1–7 behavior without metadata. For a peer starting v8 phase, host rejects any performance or out-of-order query until required phases complete; host tracks v7 successfully generated, phase, expected page, total and immutable projection. v8 one snapshot per peer; queries after completion or active stream close. If old client never begins v8, do not force it. Browser must send next query only after corresponding previous response validated; no extra heartbeat between pages. Existing 2s idle expiry, 220ms ACK timeout, 100ms freshness and 90/s limit apply. Combined v8 queries <=20/s (minimum 50ms between query sends, host remains authoritative for ordinary rate); overall metadata phase deadline 10s from first query, max 57 pages (8+49), no reset by progress; close if time budget exceeded. Host enforces phase duration on next request and expiry; never extends active watchdog. Use monotonic local timing. On any failure revoke/close peer through existing path and discard all staged data; no partial publish.

### 3.2 Mapping destination pages

Request exact keys version,sequence,kind,page:
```json
{"version":8,"sequence":2,"kind":"mapping","page":0}
```
Response exact keys kind,version,sequence,page,pages,total,detail,rows:
```json
{"kind":"mapping","version":8,"sequence":2,"page":0,"pages":1,"total":2,"detail":true,"rows":[[9,0,9,36,1],[9,0,9,38,1]]}
```
Response substitutes ordinary accepted ACK only for corresponding v8 request. Sequence uses same strictly increasing 1..9007199254740991 space as other frames, echo exact request sequence in response. Pages zero-based, total grouped rows 0..64, pages=max(1,ceil(total/8)), eight rows per page except last (total zero means one empty page). All pages consistent detail,total,pages; next page exactly previous+1; no retry/repeat/skip. Detail=false iff policy withholds destination metadata; only allowed shape total=0,pages=1,page=0,rows=[]; no target count leak. Detail=true requires mapped rows and exact v7 coverage (zero-row only if no capability; #87 denies cost-zero peers).

Row [signal,kind,channel0,number,multiplicity], fixed integers:
| Signal IDs | Meaning |
|---|---|
| 0,1,2 | x,y,contact |
| 3,4,5 | tiltYaw,tiltPitch,tiltRoll |
| 6,7,8 | accelerationMagnitude,rotationMagnitude,airStrike |
| 9..16 | drumPad1..8 |
| 17..41 | pianoKey0..24 |
| 42 | pianoSustain |
| 43..48 | pedalExpression,Volume,Wah,Sustain,Switch1,Switch2 |

Kind 0=note number 0..127; 1=CC 0..119 excluding 0,6,32,38,64,96,97,98,99,100,101; 2=pitch bend number=0; 3=sustain number=0 (CC64 display). Channel zero-based 0..15. AirStrike/drums/piano keys note only; pianoSustain/pedalSustain sustain only; pedalExpression/Volume/Wah CC or bend; switches CC; other signals valid generic patch targets. Host must apply existing InstrumentPatch and PhysicalPatchRuntime validation including calibration/response restrictions; browser cannot infer omitted calibration. Project all matching routes only, group by first four columns, multiplicity 1..64; lexicographic ascending by first four across pages, unique tuples, sum multiplicities <=64. Reject missing/extra signal coverage against v7: touch iff any 0..2, tilt iff any 3..5, acceleration iff 6 or 8, rotation iff 7, airDrums iff 8; masks exactly from corresponding IDs including sustain bit25. Reconstruct only when detail=true. Never generate default target for unavailable row. No route IDs, patch names, local/other source routes, velocity, threshold, priority, curve, release values, DAW/device IDs or host paths.

### 3.3 Optional custom labels

Following completed detail=true mapping phase, if mappingLabelsV8 advertised, request exact same fields with kind mappingLabels, start page=0. If no label consent, return empty phase (no count leak). Detail=false skips entire label phase.
```json
{"version":8,"sequence":3,"kind":"mappingLabels","page":0}
{"kind":"mappingLabels","version":8,"sequence":3,"page":0,"pages":1,"total":1,"rows":[[9,"S2ljaw"]]}
```
Response exact keys kind,version,sequence,page,pages,total,rows; rows zero or one [signal,base64url], total 0..49, pages=max(1,total). Strictly increasing unique signal IDs that exist in mapping rows; one eligible nonempty PerformanceWidget.label for exact source/signal, XY label applies x only, never auto-copy to y. Omit unsafe labels (do not truncate); label cannot expose patch name implicitly or override logical identity/targets. Unpadded canonical base64url of 1..64 UTF-8 bytes (<=86 chars); strict roundtrip, valid UTF-8, reject Cc/Cf Unicode categories, whitespace-only and malformed bytes; explicitly reject zero-width or bidi formatting controls, not normal combining marks or legitimate non-Latin scripts. Define whitespace using Unicode White_Space and test equivalent Swift/JS behavior. Browser render textContent, never HTML, attributes interpreted as URLs, script, CSS or MIDI. Optional local alias session-only; details always accessible. If mappingLabelsV8 false, no label request, host marks phase complete after mapping. Label timeout is a negotiated failure, not silent downgrade.

### 3.4 Strict decoding and exact sizes

ASCII compact JSON output; wire input must be valid UTF-8, no BOM, <=256 bytes before parse; v8 ASCII-only (label bytes are encoded). Accept only JSON structural whitespace SP/TAB/CR/LF, exact fields, no duplicate decoded member names (including escaped equivalents), no unknown keys, invalid escape/surrogate, trailing data, extra nesting, bool coercion or null. V8 integer tokens match 0 or [1-9][0-9]*, bounded range prior to conversion; reject -0, fraction/exponent even if parsed value rounds to an integer. JSON.parse/JSONDecoder alone cannot enforce lexical rules. Existing #83 RemoteFlatJSON only accepts scalars or flat numeric arrays: **do not extend it to arbitrary nested JSON**. Client v8 requests remain flat; extend typed request enum with page and exact-key validation, retain lexical token info or dedicated bounded v8 request parser. Browser v8 response parser specifically allows only array of fixed-length primitive row tuples, depth <=3 containers (object, outer rows, inner row), <=8 rows for mapping or <=1 for labels. Implement one bounded tokenizer/validated representation, then field/range checks; no duplicate-key loss through object conversion. Legacy performance parsing retains narrow existing grammar. Avoid repeated parsing or regex compilation in hot input path. QA3 measured exact scanner 116.52/124.08 us/frame vs isolated cached-regex variant 25.19/23.50 us/frame (12,000 mixed frames each round; identical 9,000 acceptances), ~4.6–5.3x in Linux microbenchmark. This is not end-to-end latency; coordinator should cache immutable compiled patterns or hand off one validated representation only after equivalence and actual-target profiling. PERF3 integration evidence pending. Do not accept nested rows from client.

QA2-01/02 decision proposal: use the same exact unsigned lexical integer rule for v1–7 versions/sequences/masks and v7 manifest masks in a separately reviewed narrow remediation; binary pedal levels for indices 3..5 and inactive slots must be lexical 0/1 (inactive 0), not rounded near endpoints. Continuous active pedal/XY/sensor values remain finite IEEE floating-point decoding with explicitly documented rounded-range semantics, valid 5e-1 accepted; don't introduce arbitrary-precision arithmetic or change established valid continuous samples. Reject BOM before decoding on both ends in strict gate. This is a coordinator decision requiring compatibility vectors; not a claim #83 already does it. v8 gate independently requires exact integer/BOM behavior. Reject ambiguous v7 manifests before enabling UI.

Executed JSON.stringify size checks in UX3: widest compact envelope detail=true with eight [48,1,15,127,64] rows and 16-digit sequence is 247 ASCII bytes; detail=false same syntactically wide but semantically forbidden rows is 248 bytes; valid empty withheld response is smaller. Label envelope with page48,pages49,total49 and 86-character base64url string is 199 bytes. Synthetic width vectors not necessarily semantically valid. Always check actual byte count on both ends, including v7; no truncation or splitting rows. Maximum 64 grouped rows/49 labels, bounded staging, exact count and multiplicity before publish. Serialize mapping rows sorted, compact; order of object keys not semantic. On any parse/encode mismatch fail closed, not normalize or repair.

## 4. Adaptive mobile UI and truthful refusal

Use existing Play / Setup / Connection arrangement. Show only mapped surfaces (disabled with reason if workload-ineligible); initial selected surface unarmed. Touch with only one axis/contact uses verified existing v1 semantics or original XY view with only mapped labels. Pads preserve logical IDs, hide unmapped. Piano keeps chromatic geometry, upper-only window selected; sustain-only standalone. Disable scale overlay unless disclosed targets prove default pitches 48+i for all enabled keys (single distinct pitch per key); no assumed notes for custom/hidden mapping. Pedals and motion show logical labels and disclosed destinations, no guaranteed wah/GM/FX, pressure/haptics or sound. Air Drums shares acceleration, no extra arm. Tablet two surfaces/pins only under approved union, one canonical controller per stream, no duplicate ownership. Setup idle-only for hitbox-moving changes; nonsensitive layout preference may persist, mapping/labels/alias/arm may not.

Rendering: user label if consented + canonical control identity; one target shows Ch(channel+1) + note name (60=C4), CC number, Pitch bend or Sustain(CC64); multiple show N distinct targets with expandable complete list and multiplicity where >1. No disclosed calibration/neutral; slider percentage is normalized input. Hidden detail: "Pad 1 · mapping details hidden"; old host: "Pad 1 · mapping details unavailable". No invented pitch or route labels. Metadata may inform display, never broaden masks or activation.

State model: Disconnected -> Pairing -> Checking controls -> Syncing mapping -> Ready -> Releasing -> Ready or Disconnected. Track each stream mapped, workload eligible, enabled/requested, permission pending, sent, ACKed, releasing; actual DAW/audio/hardware unknown. Pairing admitted establishes peer resource reservation only on verified #87-derived host. Never label locally enabled as host active. ACKed arm != delivered sample; ACKed release != actual note-off. On generic admission failure use "Connection not accepted. Request a new invitation from the Mac. The invitation, mapping or device capacity may be unavailable." Do not claim reason; no count of free slots, no automatic retry. TLS error: do not bypass certificate validation. On already-paired workload refusal: "This instrument combination is not available for this session. Disable and release an instrument to change combinations." Distinguish this from freeing whole-peer admission capacity. For unknown or pending policy: "Concurrent performance not verified"; no fabricated green latency bars. Optional idle diagnostic only observed ACK RTT with count/age, not musical latency or profile entitlement.

When scheduling fault/queue age/ACK/freshness/rate/lifecycle failure occurs: close, "Performance interrupted. Some inputs may not have reached the Mac. Mac cleanup not confirmed. Request a new invitation." Never replay. No guessed host failure reason; use specific browser-local cause when actually observed. Pagehide/blur/lock/network loss close, invalidate permission epochs, clear pending events/metadata; old ACK or permission cannot resurrect. Navigation away from active unpinned instrument: block new input, release and await matching ACK or close; pinned active stream remains visible with stop if eligible. Never hide held key/contact or move active hitbox; #84 held cancel/lost capture and active/pending XY rotation close. Normal pointer-up then lost capture must not cancel completed tap. Other pointer ownership preserved as applicable. No automatic rearm on reconnect.

Global persistent Release my controls: freeze input, cancel permissions/listeners, retain knowledge of pending sends, discard unsent canceled onsets (tell user if canceled); send only required per-stream releases/zero snapshots through one ACK lane, in valid order; if pending arm/onset reaches host, follow with release, never send unarmed motion release. If all required ACKs arrive, "Release accepted by Mac", unarm; reservation still held. Aggregate proposed <=350ms from intent, earlier individual safety deadlines dominate; if not feasible close immediately, no timer extension. Disconnect immediately closes. No raw CC123, global panic, assumed zero neutral or other owner eviction. If audible stuck output, use existing Mac stop/release path. 44px minimum primary targets (48 preferred), 320px/200% zoom, large text, screen-reader labels, non-color statuses, no modal blocking release. No added controls beyond earlier scope.
