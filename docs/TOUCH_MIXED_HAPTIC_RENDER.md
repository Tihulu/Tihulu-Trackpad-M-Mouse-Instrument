# Mixed Touch Instrument haptic performance

Base #146, exact head 8ce7569f0f4f9bda1c4a4e45b0c199365d0adaba. #144, #145 and #146 exact-head CI runs 45527887120, 45528354397 and 45528950198 completed successfully.

Source finding: after the multi-finger drum fix, a drum hit still caused the renderer to return before considering any melodic contacts. The drumPriorityUntil guard suppressed continuous pitched refreshes for the full nominal percussion duration; it could also consume a pending short melodic attack without rendering it. Repeated drum hits could keep an independently configured melodic surface silent.

The native Swift TouchHapticRenderPlan replaces this exclusive priority with one bounded physical frame per render tick. It mixes recent drum waveforms with the current melodic voice frame, preserving standalone drum and melody behavior. Mixed frames use at most 18 ms or the remaining nominal drum tail, whichever is shorter; the tail is not extended by refresh and is cleared on render token/revision change. After melody release, the remaining original tail can be issued once. New strikes replace the previous drum tail. The existing six-tone, duration and gain policy remains. Multiple sources share the motor; exact timbre, overlap/gaps under scheduler jitter and physically distinguishable strikes are not established by the synthetic tests. MIDI routing/ownership and existing timer cadence remain unchanged.

Invalidating sample publication discards queued drum attacks without resetting the buffer's held-contact set. Structural changes and Stop still reset the buffer. This is not proof of physical rearm across arbitrary input-device frame order.

Manual Diagnostics > Touch performance > Reset timing / Refresh timing now includes maximum raw-down and triggered contact counts per surface (committed active frames only), accepted/drained drum strike counts and driver calls returned/threw. No coordinates, identities, note content, new timer or per-frame UI updates. A returned driver call is not confirmation of motor vibration; the existing private driver API does not provide that guarantee. Compare counts after a controlled two/three-finger test, keeping the same settings.
