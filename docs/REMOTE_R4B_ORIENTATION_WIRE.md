# Remote R4b — relative orientation wire and host routing

R4b adds a bounded orientation-only vertical slice. Existing v1 touch/release/heartbeat messages are unchanged. The existing TLS connection, one-time pairing, Host/Origin checks, one outstanding ACK, sequence and 90/s rate limits apply. New v2 kinds: orientationArm and orientation (complete alpha/beta/gamma in device degrees), motionRelease (no axes). All other fields are forbidden. Transport retains the existing subprotocol and 256-byte bound. Host calibrates on explicit arm using 45 degree half sweep; beta/gamma outside ±80° fail closed. A successful arm produces no MIDI until a subsequent sample. No client MIDI targets or timestamps.

Host patch must explicitly map phone/tablet tiltYaw, tiltPitch or tiltRoll to CC/pitch bend; note/sustain motion routes are rejected for this increment. Router ownership is separate from touch; release returns configured neutral or restores other owners. Disconnect, stale data, heartbeat while armed, mixed active touch/motion, malformed data or replay revoke the peer and release owned MIDI. One active mode per connection is deliberate for this increment: no shared heartbeat can keep stale controls active. Separate peers may use different modes. No browser motion permission or capture UI yet; no physical claim. Accelerometer and rotation-rate routing and simultaneous independent streams remain future work. Browser permission, screen rotation/recalibration, iOS/Android TLS and DAW checks remain HOLD.

Tests in RemoteOrientationWireTests cover version/schema, explicit arm/sample/release, stale watchdog, invalid heartbeat, forbidden note routes and mixed touch. Existing v1 regression suite must pass before advancing. Stable branch untouched.
