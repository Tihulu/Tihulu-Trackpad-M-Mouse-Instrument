# R4c — opt-in browser tilt and Pocket Wah route

The paired browser can request DeviceOrientation permission only after a user presses Enable & calibrate. Missing APIs, denied permission, unavailable samples and out-of-range data do not produce synthetic motion. First valid sample establishes host neutral; relative pitch meter is a pre-mapping preview. Subsequent fresh samples are coalesced at at most 20 Hz with one ACK outstanding; never repeat stale samples. A 250 ms browser watchdog closes the connection and host watchdog releases controls. Release tilt sends motionRelease after outstanding ACK and removes listener. Screen rotation, blur, hiding, disconnect or invalid active samples close the connection; reconnect explicitly. A platform permission dialog that triggers blur may require reconnecting after permission is granted. No bypass, persistence or background capture.

Instrument Builder includes an explicit add-route button for phone pitch tilt → CC74 with 35 ms smoothing, no automatic replacement of user routes. CC74 is a MIDI filter control, not an audio effect; map it to the desired DAW wah/filter plugin. Other controls can be manually mapped; no default MIDI or audio activation. Calibrate with beta and gamma within ±80 degrees, away from singularities. Tilt and touch are mutually exclusive on a single connection. Accelerometer and rotation-rate streaming remain pending.

Node VM tests execute the actual embedded JS using fake DOM, sockets, permission and clock: denial, arm/sample/ACK/release, stale data, rotation, v1 touch regression. They run in Ubuntu CI before Swift verify. These tests are not iOS/Android or hardware acceptance. Real secure-context permission behavior, LAN/TLS, native input and MIDI effect/latency remain HOLD. Stable untouched.
