# CoreMIDI event packet traversal
Use the original MIDIEventList's inline packet storage and CoreMIDI's next-packet function rather than navigating a stack copy. Read valid callback packet words in-place for callback lifetime only; no retained pointer. UMP walk respects the message type's word length, so unsupported MIDI 2.0/SysEx/Flex/reserved payload words cannot be misread as channel voice messages. Stop at truncated message; keep valid preceding MIDI1 messages. Three pure decoder tests authored; native CoreMIDI multi-packet and pointer integration still require macOS build and physical/virtual endpoint acceptance. This assumes CoreMIDI provides valid event-list storage, not an arbitrary untrusted byte buffer. No stable changes.
