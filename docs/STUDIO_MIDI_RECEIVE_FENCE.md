# MIDI receive session fencing
The service closes the receive epoch and clears its callback under the existing lock before outgoing cleanup, while the outgoing endpoint remains enabled for releases. A callback captures the epoch at entry; every note/controller mutation checks the captured epoch inside the mutation lock. Callback closure is copied under lock and invoked outside to avoid reentrancy deadlocks. Studio additionally fences delayed main-actor notifications with a distinct MIDI session epoch (normal stop and panic invalidate it; duplicate Start is a no-op). Start publishes callback only after successful endpoint setup. This prevents work already captured in an old session from mutating a new session or UI; cannot identify a new callback delivered by CoreMIDI after restart as a historical external packet. Two pure epoch regressions authored. Native race/endpoint tests pending. No stable changes.
