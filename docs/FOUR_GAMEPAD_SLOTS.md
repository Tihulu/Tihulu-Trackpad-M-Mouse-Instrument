# Four native gamepad slots

Base #156 exact head 2f97da14c87e6ad457410d9060c91f436969b713, full CI run 45574718815 PASS.

This candidate expands explicit native controller identities from gamepad1/gamepad2 to gamepad1–gamepad4. All four can use the existing per-control note, chord, sustain, analog CC, Hold/Toggle and preset mapping policies. The native physical adapter receives a dictionary of selected slot identities, checks actual connected object identity and refuses duplicate devices; the existing two-argument binding API forwards to it. No automatic replacement/reconnection during a run. Existing mapping archive values and slot 1/2 output defaults remain valid; new slot 3/4 defaults are MIDI. Older binaries are not expected to decode new slot names.

Builder offers four slot selectors, explicit physical binding for each used slot, and an explicit source/destination map copy. Replacing an occupied copy target requires confirmation against the captured draft. All other routes remain untouched. Gamepad-only native patches with at least two slots can choose per-slot MIDI, haptic or Both; channels shared by incompatible output choices remain invalid. Local haptics still share one motor and its existing six-tone cap. Hybrid/remote mixed haptic policies have not been expanded.

The existing 16 router sessions, 64 mappings, five reserved non-gamepad local sessions, and maximum four remote peers remain unchanged. Two mapped gamepad slots leave nine remote stream sessions; four leave seven. Admission uses the existing remoteSessionLimit and remoteSessionCost checks. An individual mobile peer may need several sessions, so seven sessions does not imply seven phones. No runtime/timer additions or relaxed safety deadlines. The new four-slot limit is an engineering choice for the first expansion, not a physical capacity measurement.
