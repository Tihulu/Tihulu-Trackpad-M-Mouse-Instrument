# TIHULU Remote R2c — explicit loopback TLS diagnostic

This increment adds a user-facing Mac-only diagnostic in the existing Builder when a patch contains phone/tablet X/Y/contact routes and Native mode is selected. It does not enable LAN or a phone webpage. It does not generate, install, export or trust certificates. The user must provision a dedicated server TLS identity in Keychain (private key + leaf certificate with IP SAN 127.0.0.1, server authentication, valid dates and trusted chain). Use your existing trusted local development CA or administrator-approved certificate process; do not use a personal signing identity or disable validation. No automated trust change, certificate download or insecure mode. Keychain selection occurs only on explicit Load, and selected certificate is preflighted with SSL trust policy, network fetching disabled. URLSession independently performs ordinary TLS trust checking. Certificate/identity and invitation not persisted to patches, logs or repo.

Workflow:
1. Add phone or tablet contact -> MIDI note (and optional X/Y controls) in Builder. Select Native mode, leave MIDI OFF for first diagnostic.
2. Load Keychain identities, select the dedicated trusted loopback TLS server identity, Start loopback listener. Fixed WSS endpoint 127.0.0.1:9443, expected Origin https://127.0.0.1:9443. No browser page yet.
3. After listener ready, select mapped phone/tablet source and Run TLS + touch/release test. One-shot native URLSession client uses OS-generated binary invitation, exact Origin/subprotocol request, waits for admitted acknowledgment, sends normalized touch snapshot, waits for host delivery acknowledgment, sends release and waits for acknowledgment, closes. Timeout 5 seconds; Stop/Panic cancels and clears token. Acknowledgment proves host accepted data, not actual DAW sound or browser compatibility. Check command monitor for mapped commands. MIDI ON is optional explicit user action; use dedicated DAW input and separate channel.
4. Disconnect peer or Stop/Release All. No automatic restart. If trust or protocol fails, do not weaken policy; inspect trust chain and native handshake. Test on real Mac is pending.

Transport now acknowledges accepted data frames only after host processing and completion before next receive. Same bounded queue/peer limits and R1 watchdog. Existing default native/simulation behavior preserved. New code compilation pending. No socket/physical PASS claim.
