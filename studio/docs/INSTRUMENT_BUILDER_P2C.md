# Instrument Builder P2C — shared native monitoring

The existing TouchInstrumentService owns the single native monitor. A per-run bounded PatchSurfaceMailbox is subscribed to raw frames before musical transformation; Builder does not register or stop private callbacks independently. A lock serializes subscriber change and bounded enqueue. Shared monitor demand includes Touch Instrument, MIDI Helper, their UI previews and physical Builder. Removing one demand does not stop remaining consumers. Monitor registration has a token, stale registration callbacks are rejected, failed registration rolls back service/controller state. Physical Builder session persists across navigation; simulation still stops when leaving its page. Global Stop Builder releases just Builder MIDI controls, Panic/reconnect/window-close/termination release Builder and live sequencer. Route TIHULU Instrument Builder to a separate DAW input/channel: cross-source MIDI ownership remains per virtual source, not an arbitrary DAW merge. Existing haptic arbitration unchanged; Builder outputs MIDI only. Hardware still experimental, actual device identity, throughput and concurrent use require real-Mac acceptance. Test matrix: start Builder before/after Touch/Helper, switch pages, stop each in both orders, watchdog overflow and device loss, repeated restart, Panic, no stale output, CPU/latency. No claim of physical PASS. No new dependencies or stable release.
