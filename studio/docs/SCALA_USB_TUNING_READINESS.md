## Import contract

ScalaKeyboardImport consumes caller-provided text only; it opens no files or MIDI ports. SCL supports strictly ascending positive cents (decimal point required) or positive integer ratios (including bare integer ratios), implicit unison, 2–128 degrees including the exact terminal octave (2/1 or 1200.0), comments and CRLF. No rounding to the legacy semitone editor. Reject non-octave periods, duplicate/reordered degrees, malformed counts, exponent/NaN, overlong text (16 KiB), lines (256 bytes), descriptions (64 bytes), or ratio components above 1 billion. This deliberately rejects some valid Scala files, including unsupported period shapes and alternative syntax; never silently normalize them.

KBM accepts first/last MIDI key, middle key, reference key and positive decimal frequency, a bounded map of 0–128 slots (0 means linear degree order), explicit degree indexes within the scale period and x holes. Formal octave degree must equal the imported degree count, including for the linear subset; reject negative or extended degree entries and other formal octave conventions. Reference must be inside the mapped key range and not a hole. Derive the root frequency from the reference step, then use the existing MicrotonalKeyboardTuning model (bounded nominal MIDI domain and A4 calibration). Reject an unrepresentable reference. No guarantee that every mapped note is representable; ScalaKeyboardPreview explicitly returns tuned, unmapped, outsideRange or unavailable per physical key. Imported holes are not a license to pass original notes; an unlock policy for imported maps needs separate design and consent. SCL and KBM must be paired deliberately. No UI file picker, persistence, MIDI encoding or activation is included.

## Offline profile interchange v1

ScalaKeyboardProfile exports a bounded JSON data envelope containing only version 1, the original SCL text and the original KBM text. It preserves comments, line endings, fractional pitches, explicit holes and reference calibration by re-parsing the exact pair on import. The envelope is limited to 256 KiB; each source retains the existing 16 KiB input limit. Unknown fields (including route, device identity, activation and unlock), invalid versions, malformed data and incompatible scale/map pairs are rejected. The decoder uses Foundation JSON semantics; this is not a cryptographically signed format or a canonical cross-platform byte encoding. Import creates a new immutable preview, never edits an active mapping, writes a preference, opens a file picker, enables unlock or starts a session. A future UI must explicitly select files, preview errors, and use separate routing consent; any live apply requires neutral release and coordinator-owned integration.

Focused tests exercise exact data round trip, all 128 physical input dispositions, reference frequency, original line endings, corrupt and oversized data, invalid versions, foreign activation/routing fields and incompatible source pairs. These complement, not replace, the existing injected-sink USB scale-lock tests and native acceptance plan.

## Offline calibrated MPE member projection (TUN-03)

The physical-key map and Scala preview now reuse OfflineTuningMemberPitch for the same A4=440 receiver and explicitly selected 1–96 semitone bend range. The projection preserves physical input note and logical degree step even when multiple pitches share an anchor. Its 14-bit bend rounding uses the asymmetric MIDI endpoints (negative 8192, positive 8191). Quantization error is bounded by half a bend unit, not zero; receiver configuration and measured pitch remain separate. Imported holes, out-of-range notes and unavailable assigned pitches never bypass to original MIDI. The existing legacy unlock policy alone can return center-bend original members, independently of the tuned reference calibration. Separate physical ownership remains mandatory; neither projection allocates or sends.

Three additional repository regressions cover legacy calibrated versus original disposition, partial note/pedal cleanup retry, and ambiguous pedal release; their full repository execution is pending CI. ## TUN-04: strict profile envelope (2026-11-27)

The v1 profile is a flat UTF-8 JSON object with exactly three unique decoded keys: version (integer syntax), scale (string), mapping (string). A bounded preflight rejects duplicates including escaped aliases, nested values, trailing data or commas and non-UTF-8 input before Foundation decodes the complete typed envelope. No change to the source SCL/KBM syntax or byte caps. This supersedes the earlier documented Foundation duplicate-key limitation for this profile format only. It is not a signed format or a remote authorization parser.

Local Swift 6.2.1 regression: before the fix the 5 profile tests yielded 3 PASS, 2 FAIL with 8 assertion issues; duplicate fields could be admitted, and malformed shapes/UTF-16 were not consistently rejected. After the fix 5/5 passed, including unique escaped key and quoted/braced text round trips.

## TUN-05: source encoding interoperability and receiver readiness

SCL/KBM source text may begin with one UTF-8 byte order mark (U+FEFF). Parsing removes only that initial marker, after enforcing the original byte cap; stored source remains unchanged. Repeated or misplaced markers in data fields fail. The v1 JSON envelope remains strict UTF-8 as described above; the source-text exception is not an envelope exception. Prior exact parser reproduced a malformed error for marked inputs, after the fix both new import methods pass.

ScalaKeyboardReadiness is a bounded, deterministic offline report of all 128 input keys, using existing preview/member projection and the existing neutral-master arithmetic. Distinguishes projected, unmapped, outsideRange, unavailablePitch and unavailableMember; counts each separately. Reports reference-key disposition, theoretical target and quantized frequencies, signed/maximum absolute quantization error in cents, remaining per-member upward/downward expression headroom, and coincident-anchor key identities and distinct-step counts. No channel count or polyphony guarantee; coincident anchor groups are warnings for later ownership review, not allocations. Headroom is arithmetic relative to frozen base and is not permission to modify a fixed-bend live member. Receiver assumes A4=440 and explicitly selected 1–96 semitone bend sensitivity; no physical measurement, feedback or hardware admission. All 128 keys are accounted for; a projected reference does not imply every key is representable.

## TUN-06: bounded Scala syntax compatibility and handoff

Reference: https://www.huygens-fokker.org/scala/scl_format.html and https://www.huygens-fokker.org/scala/help.htm#mappings. The Scala format permits text after a pitch value, a formal octave field of zero meaning the final degree of the scale, and omitted trailing keyboard mapping entries. The bounded importer now accepts whitespace-separated pitch labels (space or tab), normalizes a zero formal octave to the existing scale degree count, and pads missing trailing mapping positions with nil up to the declared map size. It never uses labels to determine ratio versus cents, changes the repeating key pattern size, or treats holes as original MIDI. The profile retains source text unchanged. A missing reference key is still invalid; invalid numeric tokens, extra rows, non-octave scales, nonzero incompatible periods, out-of-range degrees and repeated/misplaced BOM in data fields remain rejected. This intentionally remains a subset: empty scale descriptions, unseparated pitch suffixes, arbitrary formal periods, negative mapped degrees, nonascending/non-octave pitches, larger ratios and alternate source encodings are not supported. No automatic normalization beyond the defined zero period.

Reproduction using exact predecessor importer blob 96aecfd967966559d6bdfc202de05225cf8a51af: four new Swift Testing methods gave 1 PASS and 3 FAIL (labelled pitches, zero period, omitted holes); final isolated package 26/26 PASS. The previous negative fixture for period 0 is replaced with incompatible period 2 for a three-degree scale because 0 is now intentionally defined by the official format; positive equivalence and negative period cases remain tested. Preserve original failing log. No hardware or native UI claim.

## TUN-07: explicit source boundaries and staged validation

It rejects VT, FF, NEL, Unicode line separator and paragraph separator anywhere in the source, including comments, rather than allowing the general Swift Character.isNewline predicate to turn hidden characters into data fields. This is a conservative input interoperability policy, not a new remote security vulnerability. Original valid source text remains byte-for-byte preserved in the profile. ## TUN-08: exact offline expression headroom boundary

The original member expression guard checked the rounded sum of encoded base cents and requested offset. This can falsely reject a request equal to the reported headroom and can admit a representable offset just beyond that headroom after rounding. The member projection now checks the signed offset against the same computed headroom interval as the readiness report, before adding the base. Only after admission is the rounded sum normalized to the existing bend interval; no tolerance, larger bend range, changed anchor, reallocation or live output is introduced. The interval is a Double arithmetic contract, not a measurement of physical receiver pitch. Zero offset still restores the exact frozen base.
