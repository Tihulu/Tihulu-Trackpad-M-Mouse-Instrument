## Import contract

ScalaKeyboardImport consumes caller-provided text only; it opens no files or MIDI ports. SCL supports strictly ascending positive cents (decimal point required) or positive integer ratios (including bare integer ratios), implicit unison, 2–128 degrees including the exact terminal octave (2/1 or 1200.0), comments and CRLF. No rounding to the legacy semitone editor. Reject non-octave periods, duplicate/reordered degrees, malformed counts, exponent/NaN, overlong text (16 KiB), lines (256 bytes), descriptions (64 bytes), or ratio components above 1 billion. This deliberately rejects some valid Scala files, including unsupported period shapes and alternative syntax; never silently normalize them.

KBM accepts first/last MIDI key, middle key, reference key and positive decimal frequency, a bounded map of 0–128 slots (0 means linear degree order), explicit degree indexes within the scale period and x holes. Formal octave degree must equal the imported degree count, including for the linear subset; reject negative or extended degree entries and other formal octave conventions. Reference must be inside the mapped key range and not a hole. Derive the root frequency from the reference step, then use the existing MicrotonalKeyboardTuning model (bounded nominal MIDI domain and A4 calibration). Reject an unrepresentable reference. No guarantee that every mapped note is representable; ScalaKeyboardPreview explicitly returns tuned, unmapped, outsideRange or unavailable per physical key. Imported holes are not a license to pass original notes; an unlock policy for imported maps needs separate design and consent. SCL and KBM must be paired deliberately. No UI file picker, persistence, MIDI encoding or activation is included.

## Offline profile interchange v1

ScalaKeyboardProfile exports a bounded JSON data envelope containing only version 1, the original SCL text and the original KBM text. It preserves comments, line endings, fractional pitches, explicit holes and reference calibration by re-parsing the exact pair on import. The envelope is limited to 256 KiB; each source retains the existing 16 KiB input limit. Unknown fields (including route, device identity, activation and unlock), invalid versions, malformed data and incompatible scale/map pairs are rejected. The decoder uses Foundation JSON semantics; this is not a cryptographically signed format or a canonical cross-platform byte encoding. Import creates a new immutable preview, never edits an active mapping, writes a preference, opens a file picker, enables unlock or starts a session. A future UI must explicitly select files, preview errors, and use separate routing consent; any live apply requires neutral release and coordinator-owned integration.

Focused tests exercise exact data round trip, all 128 physical input dispositions, reference frequency, original line endings, corrupt and oversized data, invalid versions, foreign activation/routing fields and incompatible source pairs. These complement, not replace, the existing injected-sink USB scale-lock tests and native acceptance plan.

## Offline calibrated MPE member projection (TUN-03)

The physical-key map and Scala preview now reuse OfflineTuningMemberPitch for the same A4=440 receiver and explicitly selected 1–96 semitone bend range. The projection preserves physical input note and logical degree step even when multiple pitches share an anchor. Its 14-bit bend rounding uses the asymmetric MIDI endpoints (negative 8192, positive 8191). Quantization error is bounded by half a bend unit, not zero; receiver configuration and measured pitch remain separate. Imported holes, out-of-range notes and unavailable assigned pitches never bypass to original MIDI. The existing legacy unlock policy alone can return center-bend original members, independently of the tuned reference calibration. Separate physical ownership remains mandatory; neither projection allocates or sends.

Local Swift subset tests: 13/13 pass, including 512 pitch/range combinations (128 input notes x four bend ranges) and distinct steps sharing an anchor at 432 Hz. Three additional repository regressions cover legacy calibrated versus original disposition, partial note/pedal cleanup retry, and ambiguous pedal release; their full repository execution is pending CI. No change to the scale-lock state machine, allocator, receiver setup, sustain policy or timing. Logic/MPE and USB hardware acceptance remain NOT_RUN.

## TUN-04: strict profile envelope (2026-11-27)

The v1 profile is a flat UTF-8 JSON object with exactly three unique decoded keys: version (integer syntax), scale (string), mapping (string). A bounded preflight rejects duplicates including escaped aliases, nested values, trailing data or commas and non-UTF-8 input before Foundation decodes the complete typed envelope. No change to the source SCL/KBM syntax or byte caps. This supersedes the earlier documented Foundation duplicate-key limitation for this profile format only. It is not a signed format or a remote authorization parser.

Local Swift 6.2.1 regression: before the fix the 5 profile tests yielded 3 PASS, 2 FAIL with 8 assertion issues; duplicate fields could be admitted, and malformed shapes/UTF-16 were not consistently rejected. After the fix 5/5 passed, including unique escaped key and quoted/braced text round trips.
