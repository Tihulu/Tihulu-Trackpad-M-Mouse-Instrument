# Optional Touch Bar instrument output

Native and on-screen piano and fretless controls now have an opt-in Trackpad or Both path. Default MIDI stays on the existing bridge and old profiles decode as MIDI. New output is explicitly armed, no auto-start. Both uses dedicated TIHULU Touch Bar source on the retained MIDI client, excluded from legacy bridge auto-connect. Choose a separate DAW route/channel; receiving synth must honor the RPN bend range. Local pitch bend is +/-12 semitones, expression scales level, hold/toggle sustain retains note ownership (software note sustain rather than CC64 in the new path). Vibrato/filter send MIDI controls only in Both; local versions are not implemented. Note ownership distinguishes native/on-screen piano and ribbon. Native tap timers use tokens; release, focus loss, profile changes, window close, reconnect and Panic invalidate them. Dedicated MIDI releases are scoped and failed notes tracked for retry. Haptic render uses the existing bounded note renderer. 

For now the optional output reserves the motor, like haptic chords. Chord haptic and Touch Bar haptic cannot run simultaneously; legacy sessions are not silently stopped. The shared mixer and further adapters remain follow-up. MIDI-only chords can run alongside the new Touch Bar on separate DAW routing. Test on Mac with real Touch Bar and on-screen fallback: output modes, fretless pitch and expression, shared notes and sustain, old profiles, delayed native tap/re-arm, note release and Panic, separate MIDI source, conflict refusal and no auto-start. Core tests do not prove hardware function.
