# TIHULU Expressive Controls — cross-device virtual pedals and performance macros

Status: approved design extension, not implementation or hardware verification. Keep all existing modes, stable v0.2.3, saved workspaces, TouchBarProfile, TiltMIDITarget, MIDI Helper assignments and instrument patches unchanged. No rewrite or new mandatory dependency. Existing master plan sections 4–10 already establish these sources and musical targets; this document specifies a common cross-device workflow and incremental delivery. Actual app name unchanged.

## Existing implementation and gap
At #49 HEAD e34f4f43621f088f79352fa2a3053520c458f034, TouchBarProfile has tiltTarget disabled/filter CC74/expression CC11/vibrato CC1/pitch bend and calibrated 50–135 degree defaults; StudioController.applySimulatedHingeAngle delegates to touchBarValue. Native hinge support is experimental. Touch Bar zones, MIDI Helper and dedicated Builder MIDI routes exist. SensorRouter handles normalized input, calibration, hysteresis, priority and ownership. PhysicalPatchRuntime supports primary-contact X/Y/contact/contactSize for Trackpad/external touch surfaces; no verified pressure or per-device identity. PatchGraph compiles typed input/calibration/output to InstrumentPatch. Reuse these; do not create a competing real-time engine. Existing controls remain available until optional new adapters reach parity.

## A single reusable expressive mapping
Source adapter + capability -> calibrated normalized stream/gesture -> optional smoothing, range, curve, invert, dead zone, hysteresis, slew/rate limit -> gate/latch/modifier/hold or toggle -> one or more MIDI targets or optional local effect parameters. Macro controls can fan out with individual curves/ranges and opposite polarity. Preserve source and session identity. Standard presets for wah, whammy, expression, volume, pan, vibrato, tremolo, filter/resonance, Leslie, reverb/delay, freeze, looping, crossfade, spatial mix, synth morph, arpeggio density/rate and transport. Wah is a control assignment, not a guaranteed effect: CC74 brightness/cutoff as a convenient starting point, CC4 foot controller/custom CC via DAW MIDI Learn; expression CC11, volume CC7, modulation CC1, pan CC10, sustain CC64, pitch bend negotiated range. No universal CC for plug-in-specific parameters. Direct local audio DSP only after the separate audio engine is implemented. Haptic feedback optional via existing safe arbiter, not a claim that haptics reproduce an audio wah.

Each preset declares neutral/release behavior (return to calibrated heel/center or hold last for non-gate controls, explicit reset), channel/endpoint, ownership and takeover (priority, soft pickup, later blend with bounded values). Note/sustain release is mandatory regardless of latch. Separate output range and input calibration. Never move multiple devices' parameters unexpectedly; detect same target collision, offer scoped target lease or explicit blend, keep existing dedicated endpoints. DAW routing and receiving plug-in mapping documented, no claim of receiver acknowledgement. Explicit arm, independent stop, panic, disable/reconnect/sleep releases; no output during editing or calibration unless user opts into preview. Rate limits, coalescing continuous updates while preserving gate edges, local monotonic time, no delayed stale actuation.

## Source capability and creative presets
| Source | Inputs, subject to detection | Examples |
|---|---|---|
| Trackpad | X/Y, contact, contactSize, verified pressure only if available, multi-contact gesture after identity validation, relative motion | XY wah+resonance, slide whammy, two-finger crossfade, thumb modifier, ribbon vibrato, scratch, virtual pedal with heel/toe zones |
| Magic Mouse | transformed X/Y, contact/size, supported scrolling or relative movement; no assumed IMU or force | swipe wah, vertical expression, vibrato ribbon, DJ crossfade, touch/release freeze |
| Touch Bar | native/on-screen ribbon, slider, button, zones/pages; simultaneous controls where verified | pedal strip, macro bank, effect bypass, wah+delay, hold modifier, scene morph |
| MacBook hinge | validated read-only angle, direction/angular speed only if samples support it | slow wah, filter, orchestral dynamics, gravity macro; no forced repetitive movement, no interference with lid/sleep |
| Phone/tablet touch | multitouch coordinates, contact lifecycle, supported pointer pressure, layout and orientation | pocket pedalboard, dual XY, virtual foot controller by hand, DJ decks, chord/pedal combinations |
| Phone/tablet motion | calibrated orientation roll/pitch/yaw (absolute heading only if available), rotation rate, acceleration with/without gravity, shake/gesture; browser permission and null capability checks | handheld tilt wah, wrist whammy, angular velocity vibrato, shake percussion, bowing, conductor dynamics, air theremin, two-axis synth morph, steering-wheel pan |
| Phone/tablet additional | camera landmarks, mic envelope/breath/beatbox, optional supported proximity/ambient light/native haptic feedback only after capability and privacy review | pinch wah, breath expression, mouth wah, shadow/filter experimental, tap feedback; no raw media upload by default |
| Mac camera | Apple Vision local hand/body points and confidence, pinch distance, palm angle, wrist rotation, hand position/speed; face/body optional, depth only if actual depth hardware | air wah, two-handed synth, conductor, hand aperture filter, air whammy, posture macro, virtual pedal by visible foot only after body pose validation |
| External | authenticated MIDI CC/pitch bend/pedal, OSC, supported controller axes | integrate physical expression pedal or joystick |

Phone motions are not absolute displacement: no integrating accelerometer to claim reliable position; neutral reference and orientation wraparound handling, coordinate frame correction on screen rotation, relative yaw drift warnings, sensor dropout and tab-hidden handling. Never require throwing a phone, unsafe foot use, or forced hinge movements. Phone PWA defaults touch-only; secure HTTPS/WSS and explicit permission for motion/camera/mic, capability negotiation per session, local derived data only, no Internet required. Native mobile optional when justified by unsupported browser features. Camera confidence threshold, lost-tracking watchdog, local inference with bounded frame rate, no default recording, bystander privacy.

## Example hybrid instruments
- Cyber Guitar: Trackpad strings -> notes/MPE, Magic Mouse Y -> vibrato, phone pitch -> wah, phone roll -> whammy, Touch Bar -> effect bypass, optional hinge -> slow volume.
- Air Wah: pinch aperture -> filter sweep, other hand controls resonance, loss of tracking returns configured neutral, notes from existing DAW.
- Pocket Pedalboard: phone screen touch to arm one macro, gyro roll/pitch drive two targets, release freezes or returns according to preset, buttons switch effects without remapping.
- One-Man Orchestra: phone conductor gestures -> expression, camera hand height -> dynamics, Trackpad chords, Touch Bar articulation, Mouse reverb.
- DJ Motion: Mouse crossfade, phone rotation -> filter, screen pad -> loop, camera gesture -> freeze only with deliberate modifier.
- Anatolian Expressive: trackpad fretless/makam tuning, phone roll ornament depth, finger ribbon bend, touch bar rhythm/aksak switch. No assumption DAW supports microtonal tuning.

## Incremental integration
E0: document and lock compatibility, #49 baseline CI; no existing code changes.
E1 (P2 Builder next increments): reusable expressive preset factory and typed target metadata; compile to current SensorMapping routes, factory templates for Trackpad/Mouse and simulated sources. Extend optional schema only when needed. Tests for archive compatibility, calibration, fanout and channel/target validity.
E2 (P2/P4): optional output-range/smoothing/dead-zone/slew, neutral policy, takeover and macro processing in shared engine. Use optional fields with legacy defaults; state per owner. Bounded deterministic tests for stale release, conflict and no regressions. MIDI Learn captures only intended CC and never arbitrary commands.
E3 (P2/P4): wire native/on-screen Touch Bar and read-only hinge adapters to shared session path behind opt-in. Preserve original quick controls and tilt profile; explicit migration/copy, no double output. Physical surface controls use already shared native monitor; no synthetic pressure.
E4 (P2): local camera hand controls with confidence/loss gate, opt-in; benchmark M2 8GB with DAW.
E5 (P3): authenticated LAN remote PWA touch widgets, then orientation/gyro/acceleration with secure permission, calibration, motion presets, disconnect and hidden-page releases. Reuse planned remote/Jam rather than second server.
E6 (P4): multi-axis/modifier macros, recording/editing/export of automation, per-device layout and hybrid presets. Optional phone microphone/camera derived input and native features based on capability. P5 local DSP/advanced effects only after audio engine acceptance.
Do not block current stable-first release, existing Builder layout work or optional AI backend roadmap. No heavy AI needed in pedal path; camera uses local vision, AI generation remains separate/off by default. Optional cloud/remote GPU is never in a real-time control loop.

## Acceptance
For each supported source test actual availability, calibration endpoints, invert, mapping to a real DAW plug-in, smooth sweep without stuck controls, gate/release/lost connection, simultaneous other instrument, routing conflict, sleep/reconnect, explicit Stop/Panic, no idle sensor activity, bounded queue, p50/p95 latency and jitter. Measure on reference M2 8 GB and representative other hardware. Test iOS Safari/Android and native Touch Bar/no Touch Bar separately. Unknown sensor is unsupported, not fake. Verify current hardware claims physically. Documentation-only E0 makes no PASS claim.
