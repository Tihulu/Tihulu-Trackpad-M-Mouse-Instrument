# TIHULU Remote R2a — loopback TLS WebSocket transport

R1 four checks passed. This increment implements a deliberately isolated macOS transport, not an enabled product server. It binds only 127.0.0.1, uses a caller-supplied SecIdentity, TLS 1.2 minimum, Network.framework WebSocket message-size cap, exact Host/HTTPS Origin/subprotocol checks, binary 32-byte one-use invitation followed by text R1 frames. No default certificate, trust bypass, plaintext mode or LAN advertisement. OS SecRandomCopyBytes generates invitations. Native transport limits six concurrent handshakes/connections, 24 admitted connection attempts per minute, five-second invitation deadline, two-second admitted idle timeout, one outstanding host event per connection and bounded 32-event mailbox; overflow closes connections. R1's 350ms active watchdog and frame rate limit remain host responsibilities. Transport IDs never accepted from clients. Host must call R1 admission for each invitation, acknowledge only accepted frames, close expired/revoked connections, and release all outputs on transport fault/stop. This bridge is intentionally not yet wired to StudioController: no UI or listener starts in this commit. No standalone second MIDI engine.

Next R2b: implement host orchestration and deterministic integration tests for admission, stale event fencing, stop/revoke, then certificate provisioning/trust instructions and explicit selected LAN bind, HTTPS browser page. Verify actual TLS handshake on macOS before LAN enablement. The host must provide the matching HTTPS origin and phone trust chain; no claim of secure phone connectivity or network penetration-test pass. Native transport compilation and three pure core tests run in CI. Stable unchanged.

References: Apple Network framework documentation, Creating an Identity for Local Network TLS; NWProtocolWebSocket.Options.setClientRequestHandler and maximumMessageSize.
