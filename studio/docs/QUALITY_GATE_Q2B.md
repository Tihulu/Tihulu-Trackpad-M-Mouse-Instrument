# Quality gate Q2b — candidate shared frame arbitration

Scope: hardware-independent arbitration of bounded haptic frames. No production driver integration, UI, feature expansion or change to current instrument sound. Q1 terminal retirement and Q2a source fences remain in use.

One lease and one latest frame per source kind (touch, incoming MIDI, chords, Touch Bar, sequencer, speech). New lease replaces that source only; explicit release or clear, expiration and global release prevent stale state. Host monotonic time; backward/nonfinite timestamps rejected. Strict existing safety band, six tones, level 0–1, frame duration 0.5–120 ms; invalid input is rejected and clears the current lease's frame. Render slices at most 18 ms and never exceed remaining contribution duration. No queue/catch-up or background work. Single-source shape and gain are preserved within the slice. Candidate multi-source policy: effective per-tone weights account for driver amplitude normalization; exact matching frequencies deduplicated by maximum weight; deterministic priority-ordered round-robin selection within the six-tone limit; bounded gain. An explicit exclusive frame (e.g. speech) temporarily suppresses continuous sources; expired frames never replay. This is not an acoustic mixer, and does not guarantee that different instruments remain distinguishable on the actuator.

The class of producers remains unchanged. No private-framework calls from the core. Next step: verify CI, then connect a single serialized hardware owner to a limited pair of note-producing sources in a separate gated change, with legacy output retained for A/B and no new feature flags exposed until usable. Producer clock translation, per-device identities, per-source failure reporting, actual tick scheduling, stop/revoke ordering and idle resource usage require integration tests; transient drums and speech require dedicated timing tests before migration. Do not relax current motor exclusivity before a verified integration. Do not treat synthetic tests as a physical acceptance.

Tests: solo shape/gain/duration, overlapping tones and scoped release, deterministic six-tone budget, exclusive expiry, old leases and invalid input, replacement/no replay and earliest expiry. Hardware acceptance after integration: compare solo output to existing versions, measure p50/p95 latency and CPU, audition mixed notes, test source loss and rapid rearm, validate zero post-revocation submissions with mocked driver and actual Panic/Reconnect, preserve MIDI and drum timing. No stable release.
