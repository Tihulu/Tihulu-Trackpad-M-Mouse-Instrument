# Instrument Builder P2D — visual patchbay

The first editable typed patchbay uses three columns (sensor input, calibration processor, MIDI destination) with explicit connection menus, shared inputs/processors, fan-out, add/remove and calibration/gate/channel/priority editing. The graph compiles to the same SensorMapping routes as the existing list editor; applying only updates the draft and never starts hardware or output. Cancel/reset leaves the saved instrument unchanged. Validation bounds each column to 64 nodes, requires unique valid IDs, rejects dangling connections, invalid calibration/gates and reserved CC configuration. Directed typed references cannot form cycles. JSON archive remains the existing InstrumentPatch schema, reconstructs grouped equivalent nodes on reopen; unused nodes and visual arrangement are not persisted. Three core tests: route roundtrip, actual router fan-out and scoped release, invalid graph rejection. No arbitrary multi-stage graph, drag-wire canvas, haptic destinations or custom performance layout yet. Real hardware/DAW acceptance pending. Stable unchanged.
