# TIHULU Remote R3b — experimental explicit LAN binding

Prior R2c/R3a CI 4/4 each. This increment enables an experimental candidate LAN path only after the native trusted loopback probe succeeds in the current app process. Stop the loopback session, explicitly select LAN, refresh local active IPv4 interfaces, choose one RFC1918 numeric address, select a dedicated Keychain TLS identity whose certificate is valid/trusted for that address, and confirm trusted network + phone certificate trust. The controller and WSS bind the same selected address (9444 and 9443); never wildcard, public DNS, discovery broadcast, automatic start or plaintext fallback. Host preflight checks the selected address, not phone trust; phone must independently validate both TLS endpoints. Do not bypass trust or forward ports. No certificate generation/import or key export.

Page, script CSP, HTTP Host and WebSocket Origin/Host derive from the validated numeric endpoint. QR contains only the HTTPS controller page address, not the one-use secret. Enter the separate 64-hex invitation within 60 seconds. Address and identity selection remain local/session-only, no repo/log persistence. Four peers max, existing bounded protocol and watchdog, extra page request rate cap. Native diagnostic remains loopback only. Stop/Panic releases and closes both listeners. Two core tests cover canonical address allowlist and exact origin binding. Real trusted loopback, selected-address socket binding, browser on iOS/Android, reconnect, certificate failure, interface changes, latency and actual MIDI sound require physical acceptance; no claim of tested LAN connectivity yet. Stable untouched.
