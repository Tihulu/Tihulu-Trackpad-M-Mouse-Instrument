# TIHULU Remote R2b — host orchestration

Internal explicit loopback integration only. StudioController can accept a caller-created RemoteLoopbackTransport in native test mode when phone/tablet routes exist. Normal user-facing Start does not create or enable it; certificate provisioning, trusted web origin and real socket test remain required. No LAN listener or plaintext fallback.

RemoteHostBridge binds transport-generated connection IDs to R1 peer IDs, admits only after listener ready and one-use invitation, validates host receipt age (<100 ms), expires old owners before accepting new frames, drops queued events for disconnected connections, revokes malformed/expired peers and fences retired bridges. Host receives MIDI commands through the existing Builder delivery ledger before transport acknowledgment; MIDI failure retires the Builder. Stop/Panic closes transport, retires bindings and releases ledger; transport fault stops entire Builder safely. Core bridge stop releases remote owners only; the application uses full Builder stop on fault. OS random invitation via existing transport; host-only revoke and peer status. No logging/persistence of tokens. Three deterministic host integration tests. These exercise the real shared router but not socket/TLS handshake, native certificate trust or phone connectivity. R2a test macro correction precedes this branch. Stable unchanged.
