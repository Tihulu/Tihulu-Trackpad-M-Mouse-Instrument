# Quality gate Q1 — terminal actuator lifetime and reconnect

Scope: first remediation for the product/technical review on PR #29. No new instrument features. The driver uses one tested lifetime gate for open, play, monitoring and close; terminal retirement drains any currently executing operation and denies later submissions or implicit reopening. Reconnect creates a fresh driver. Retired driver cleanup cannot clear a subsequent session's touch bridge. Panic first stops producers then retires the driver; generation guards discard queued capture, surface and MIDI callbacks from the old engine. Explicit reconnect resets active sessions, waits for an outstanding speaker stop before rebuilding, never resumes a performance. Normal per-mode stop and persistent MIDI graph are unchanged; explicit reconnect may recreate endpoints and requires DAW verification.

Evidence: platform-independent mock gate tests cover terminal/idempotent retirement, in-flight drain, rejection and fresh session creation. This is not a mock of the private Apple API, nor proof of hardware stop latency. Existing multiple motor writers are not yet unified; the gate is a lifecycle fence, not a mixer or per-source arbitration. Further gates: per-source revocation, true transport completion and loop length, error telemetry, exact-main integration, native hardware regression, UI/project simplification and approved icon integration. Do not expand feature scope or publish stable until accepted.

Native acceptance: press Panic repeatedly during each legacy and optional output, capture start/stop and simultaneous MIDI/touch; verify cursor free and no motor reopen until explicit user action; reconnect during each active mode, confirm no stale UI state or old notes, check Logic routes and iPhone mic transition, verify no unintended touch-monitor loss, review permissions. Record physical results separately from CI.
