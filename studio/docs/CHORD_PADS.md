# Chord Pads - first independent instrument module

Eight pads generated from root, pitch collection, scale stacks and inversion; custom absolute-note voicings override individual slots and survive root/scale changes. Includes major/minor, church modes, pentatonic, blues and explicitly 12-TET makam-inspired Hicaz, Nihavend, Kurdi and Hicazkar collections. These approximations are not authentic makam tuning, seyir or traditional harmonization. Future microtonal MPE/MIDI tuning requires receiver capability and separate tests. Reference: Can Akkoc et al., Experiments on the Relationship between Perde and Seyir in Turkish Makam Music (2015); makam pitch collections and melodic rules must be distinguished.

Dedicated Chord Pads page and optional shared on-screen strip in all other modes, including Performance, Touch Instrument, MIDI Helper, Touch Bar & Tilt, Sequencers and Mapping Lab. The strip uses the same bank and output, not duplicated state. Physical Touch Bar chord zones, trackpad/mouse chord layouts, phone and camera triggers and chord sequencer insertion are planned adapters; no claims of implementation. Local bank persistence is independent of legacy workspace JSON; active/armed state never persisted. Custom note editor currently accepts MIDI numbers. Future UX: note picker, chord library, chord progressions, inversions per pad, strum and arpeggio, export/import multi-bank presets.

Output: explicitly armed MIDI-only dedicated virtual source using existing retained process client; no new input port and no haptic or legacy MIDI state mutation. Existing bridge excludes this source from auto-connect; route a separate Logic input/track/channel to avoid collisions if the DAW merges sources. Same-bank overlapping notes reference counted. Timed gate or latch, scoped Release All, disarm, page/strip disappearance and app deactivation release notes. Panic and reconnect disarm. Failed sends cause fail-closed and best-effort note-off retry, not a claim of delivery. No changes to existing sequencer/touch/voice/speaker algorithms.

Acceptance: core tests verify all scale/voicing combinations, custom validation/persistence, note ownership and original channel release. Mac test: select dedicated endpoint in Logic, play all pads, overlap C and Am, release each, latch/timed, navigate/hide strip, switch app, Panic, reconnect, simultaneous legacy instrument on separate track/channel, confirm no feedback into haptic MIDI input. Test invalid custom notes, restart without auto-arm, and CoreMIDI loss. Do not release stable until stacked CI and physical acceptance. Verify real MIDI routing before marking hardware pass.
