# Q4a — musical transport and playback state

Pattern loops preserve full musical length including trailing rests. Fixed monotonic cycle origins prevent normal drift; a fully missed cycle re-anchors, expired events are skipped, and loop tails are limited by the boundary. One-shot material waits for the last frame or declared duration, whichever is later. One request generation covers notes, drums, voice, file, sweep and test tone, rejecting stale async render results and completion callbacks. New requests cancel earlier scheduled work; Stop/Panic invalidate callbacks. Scheduled output errors surface in the UI. No new dependencies or changes to tone/drum profiles. Five core timeline tests. Actual scheduler and hardware timing still require native acceptance: multiple BPMs, one-hit loops, silent final beats, rapid replacement, Stop/Panic and CPU. No sample-accurate or MIDI clock claim. Q3 MIDI reliability remains open. No stable release.
