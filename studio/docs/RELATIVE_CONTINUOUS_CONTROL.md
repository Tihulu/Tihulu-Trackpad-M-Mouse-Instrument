# Relative continuous control — candidate contract

Status: source-level implementation and portable tests; not universal live support or Logic feedback acceptance. Absolute remains default. Use the existing response editor for manual relative routes.

- **Absolute:** calibrated position maps directly to the configured output range.
- **Relative:** the first eligible input anchors the origin without writing MIDI. Subsequent signed displacement, gain and optional smoothing produce a bounded wire value from the selected reference. Do not accumulate quantization error or use position mode for note/strike/gate inputs.
- **Manual:** explicitly configured normalized value. It may differ from the actual receiver, so the first movement can still jump.
- **Last delivered:** an adapter's verified successful local send for the same endpoint/channel/parameter. It is not a receiver acknowledgement.
- **Receiver confirmed:** actual authorized, fresh parameter feedback for the same receiver endpoint/channel/parameter identity. Standard outgoing MIDI and remote transport ACK do not supply this.

`SensorRouter.provideRelativeReference` is a host-only API. The adapter must establish actual identity and provenance; it must not pass arbitrary remote data, inferred values or its own outgoing intent. Route and session are checked by the router. Evidence is single-use, at most 250 ms old at admission, not future-dated, within the configured wire range, and must advance the session/mapping evidence watermark. A sample older than the latest session receipt is rejected. Adapter must acquire a new sample after actual release/cleanup. No fallback to manual when a live reference is requested. Missing evidence or contention requires a new real clutch. Relative routes initially require exclusive targets.

## Adapter and acceptance inventory

| Surface | Required start/release evidence | Remaining work |
|---|---|---|
| Trackpad/Magic Mouse | stable contact identity and accepted native frame; lift or source loss | direct legacy helper ownership, contact-set change, per-axis mode switch |
| Touch Bar | touch begin/end and selected control | existing continuous owner and synth bank integration |
| Browser/iOS/Android XY | explicit contact owner, arm/release ACK and host admission | host-owned route capability/configuration revision, no second transform |
| Camera/Air helper | eligible tracked hand and gesture activation; identity/permission/loss | no reuse of cached samples; per-axis capture and re-arm |
| Measured XYZ/D-Beam | verified calibrated volume, X/Y/Z independently; loss or exit | preserve measured-depth capability and 150 ms gate; no fabricated depth |
| Gyro/tilt | angular position, explicit arm/release | unwrap at angle seam with calibrated units; rate/magnitude are not angles |
| Gamepad/lid/external | explicit start and scoped release | device-specific arbitration and feedback support |

Existing ordinary lift, expiry, Stop, Panic and ledger cleanup remain authoritative. No new hold-last behavior is introduced; pitch bend and safety cleanup must remain neutral as appropriate. MPE member tuning bends are reserved until expressive offset composition is independently proven. Mode/target edits require disarm and fresh re-arm; retain legacy archives and do not change wire protocol without negotiation.

Tests must cover no initial send, movement both directions, clamp and return, invalid/stale reference, cross-device contention, release/re-touch, cancellation, calibration and mode edits, smoothing, angular seam, missing feedback, actual DAW route/parameter confirmation and separate physical acceptance. Source/fixture tests are not hardware or receiver evidence.

### Native helper planner candidate and temporary capability fences

`NativeHelperRelativeClutch` accepts complete, strictly ordered frames from one Trackpad or Magic Mouse contact. The initial genuine neutral frame is mandatory; the first contact anchors every configured relative lane without emitting. X, Y and contact size have independent wire references, bounds, gain and smoothing. A second contact, a different ID, a foreign surface, invalid data or regressing receipt retires the clutch; wait for actual neutral before accepting another touch. A host must honor releaseRequired, retain any failed cleanup debt, enforce native freshness and block permission/identity loss; this planner alone cannot prove any of them. It is not yet wired to the native helper UI or MIDI sender. A new gesture with manually configured lanes uses those configured reference values, not a measured receiver value.

Current remote pedal lane identities do not establish whether a source is a continuous control or binary gesture after a same-family mode switch. Relative on pedalExpression/pedalVolume/pedalWah is intentionally rejected until a reviewed source-mode/route binding exists. Relative on wrapped yaw/pitch is also rejected until a seam-safe angle adapter is bound. Absolute behavior stays unchanged. Rotation and acceleration magnitudes are level differences, never angles. This is a temporary capability restriction, not a permanent omission from the feature scope.

### Angular and native output planning candidates

`RelativeAngularClutch` is a single-axis wrapped-angle preprocessor. Host supplies a newly admitted explicit clutch, ordered local receipt and raw degrees in [0,360). For pitch domains expressed in [-180,180], the adapter must convert units/domain without pre-clamping or losing the seam. It emits a normalized origin of 0.5 and bounded subsequent normalized positions for the existing `RelativeControlGesture` exactly once. Adjacent step ambiguity or an over-limit jump retires the clutch. The internal accumulated displacement is not clipped at the output edge; a return along the reverse path restores the origin. Total unwrapped travel is bounded at 3600 degrees; exceeding that retires the clutch rather than losing the origin. Default 90-degree adjacent-step cap and 45-degree center-to-edge sweep are candidate preprocessing defaults, not new live safety deadlines.

A wrapped sample cannot prove that the physical axis moved less than 180 degrees between receipts. A real adapter must establish adequate sample cadence and credible motion bounds, preserve its existing freshness gate, and retire on tracking/permission/identity loss. No heading, orientation fusion, or physical gyro acceptance is claimed. Relative on remote yaw/pitch remains fenced until this adapter is actually bound and validated. Rate and acceleration remain level differences, not angle integration.

`NativeHelperRelativeOutputPlan` checks the configured target set against all three other legacy owners and MPE-reserved channels, not merely the current effective winner. Anchor requires the prior helper owner to have been released and does not submit a reference or claim a wire lane. Sparse movement retains previously owned unchanged lanes and uses the existing gain/release policy. No RPN or new hold-last policy is introduced. Unknown/duplicate targets, reserved CCs, out-of-range movement, unrelated previous helper lanes and incompatible prior RPN snapshots are refused. A failed plan is not a neutral send. The caller must retire the clutch and handle cleanup with the existing debt-aware output ledger.

The output plan is a pure snapshot, not an atomic lease or transport transaction. A host must serialize the ownership check with existing admitted send paths, check every actual attempt, disarm after loss or competing producer, and keep failure debt visible. In particular, an empty plan must not be interpreted as an implicit release, and a matching stale helper snapshot cannot by itself prove that a new gesture is valid. Actual host wiring, native UI, endpoint binding, DAW feedback, and physical acceptance remain outstanding.

### Receipt retirement and admitted transaction

The angular preprocessor now retires every finite, nonnegative, strictly advancing observed local receipt before checking angle validity or clutch phase. Rejected begins, duplicate explicit begins while active, and blocked updates cannot subsequently permit an older queued sample after end/rearm. Invalid or regressed clocks never advance the watermark. A host must still validate receipt freshness before passing samples; the preprocessor is not a wall-clock or remote-clock trust boundary.

`NativeHelperRelativeOutputTransaction` joins the pure output plan to the existing `LegacyContinuousOwners.replaceAdmitted` transaction. Anchor does not send MIDI or install helper ownership. Movement compares the expected helper snapshot, validates reserved channels and competing owners, and advances only the individually admitted successful prefix. On denial, conflict, failed send, or expiry after the last send, retire rather than retry movement. Failed or ambiguous actual attempts are still the transport's debt, even when absent from the committed snapshot. A later rearm requires genuine neutral, empty helper ownership and explicit transport-clean evidence. Ordinary lift also retires; no new hold-last policy.

This is a portable host admission component, not a call site in the legacy MIDI service. Before connecting it to StudioController and MIDIHapticService:
1. Use the selected source-local admitted frame and preserve the existing publication and per-send receipt fence. Do not derive a fresh clutch from combined cached contact frames.
2. Persist one transaction across its full clutch and cleanup. Mode/target/permission/orientation changes retire it. Do not drop the transaction to bypass cleanup.
3. Serialize competing legacy continuous producers and MPE allocations with helper retirement; merely checking at the next helper frame is insufficient, because a higher-priority producer could acquire and release a lane between frames, restoring a stale helper value. Keep the existing absolute-owner semantics outside the explicit relative session.
4. Route admitted updates through the actual send/debt ledger, not an outgoing-intent cache. Scope cleanup to the helper, preserve independent sustain, and require transport recovery when sends fail. Do not expose a live selector before the competing-owner interlock and native integration tests are reviewed.
5. Keep receiver-confirmed feedback distinct from last local delivery and manual references. No automatic manual fallback when a feedback-based route is selected.

These gates do not change the live timeouts or authorize hardware. The local transaction tests use the exact production legacy arbiter and candidate plan/clutch/gesture; other policy/type dependencies are minimal test fixtures and wire success/failure is simulated. Full repository CI and actual native/DAW acceptance remain separate.

### Tokened legacy owner interlock

The native relative transaction now reserves its target set in the production `LegacyContinuousOwners` arbiter using a local UUID lease. The lease is not a MIDI endpoint reservation or receiver acknowledgement. Anchor requires an empty helper snapshot and no overlapping arbiter owners. Only the matching active token may submit relative movement; untokened helper writes retire the relative intent instead of reviving it. Ordinary release of any reserved helper channel retires the whole clutch; an unrelated channel does not.

Competing admitted or non-admitted legacy owner writes withdraw the entire relative helper snapshot before installing competing intent. Cleanup uses the existing neutral/persistent-gain policy; a later competitor release cannot restore a cached relative value. For admitted replacement the cleanup attempts precede competing onsets, and a denied/failed cleanup aborts that competing transaction. Failed or skipped wire cleanup remains the actual transport ledger's debt, even though logical relative intent was removed. Subsequent service admission must still honor that debt; logical withdrawal is not confirmation of delivery. The matching retired lease is cleared only after actual cleanup and genuine neutral are confirmed by its host. Absolute behavior is unchanged in the absence of an explicit relative reservation.

This interlock covers the legacy arbiter's replace/set/admitted/release paths. It does not yet establish exclusive access to all direct CoreMIDI writes or future MPE member allocations; those paths, actual source-local frame binding, native editor selection, receiver feedback, and hardware acceptance still require review and host wiring. Do not expose a live switch or claim physical support solely on the basis of this core change. Existing safety deadlines are unchanged.

### Source-bound session and manual configuration

`NativeHelperRelativeSession` is a source-to-output adapter for one selected physical surface and one monitor epoch. It accepts only an advancing publication sequence beyond the arm boundary, an increasing original receipt, an admitted complete source-local observation, and an explicit current host permit. It invokes begin/move/retire callbacks but never owns transport or proves delivery. Initial neutral and later rearm require actual selected-source empty evidence and successful cleanup. Failed begin, failed movement, denied admission, stale stream, invalid selected-source observation, or cleanup failure retire the clutch. A fresh sample arriving after a stale active stream cannot mask the missed deadline. Explicit close permanently rejects this session's later callbacks. Different source/monitor frames are ignored, never treated as release. The host must supply the existing freshness bound, schedule expiry on the serialized execution context, preserve receipt/publication fences on actual attempts, and verify admission again after synchronous sends; the test-only 125ms bound is not a production timeout change. A host stop/configuration change must close the session and keep unresolved debt until recovery; do not replace the transaction just to evade genuine neutral.

`NativeHelperRelativeManualSettings` is a declarative candidate for the first single-surface Helper UI. X has an independent 14-bit bend reference, Y and contact size independent 7-bit CC references, each with gain; smoothing is bounded. Defaults (bend center, Y zero, size full) are explicitly manual, not the Logic parameter value. Invalid or non-manual reference provenance is rejected. Disabled assignments create no lane. The first UI must explicitly label manual reference and require valid target/selected-surface configuration, existing sustain separation, no implicit RPN range configuration, and explicit stop/re-arm for mapping/mode changes. Mixed Absolute/Relative axes, both-surface relative mode, feedback providers and physical acceptance remain unimplemented.

The legacy arbiter now checks **effective** pitch-range changes on a reserved relative channel before permitting competing owner updates. A pure staged replacement preview includes range fallback from release, and preempts only when an actual range operation would be emitted, not unchanged-range bend motion or another channel. A failed admitted cleanup prevents the subsequent range update. This resolves the direct-CC vs private range-operation policy asymmetry at the legacy arbiter boundary; other virtual endpoints are not protected by this local reservation. The user must route separate MIDI endpoints to separate receiver targets or explicitly verify their interaction.

No existing StudioController or Helper selector invokes the new session yet. The next native call-site work must preserve selected surface identity, orientation, actual raw receipt and neutral evidence, bounded cadence watchdog, separate sustain, explicit disarm and cleanup recovery. Do not make a new UI mode appear live before those gates are bound and tested. The new session/manual-setting local tests exercise the exact portable sources and simulated callbacks; full native and range-policy regression CI remains separate.
